# ITA Lab — מתכנן מסלולים פיזיים (גרסה 2)

אב-טיפוס עצמאי, בלי שום חיבור ל-ITA האמיתי. המטרה: להוכיח שהמנוע יודע לחשב
מסלול פיזי נכון בין שני פורטים — כולל סוג כבל, קיבולת ורדונדנטיות A/B —
ולהציג את זה בממשק שדומה ל-ITA, לפני שנוגעים במערכת החיה.

## הפעלה (Windows)

```
cd ita_lab
pip install networkx
python generate_topology.py
python server.py
```

הדפדפן ייפתח לבד על `http://127.0.0.1:8800`. לעצירה: Ctrl+C.

`networkx` היא התלות היחידה. השרת עצמו בנוי רק על הספרייה הסטנדרטית של
פייתון (`http.server`) — בלי Flask, בלי npm — כדי שזה ירוץ גם ברשת סגורה
בלי להתקין כלום.

## איך עובדים בממשק

1. **מפת החווה** (ימין) — שני הפודים, כל אחד עם שדרה S ושדרה N. כל מסד
   מציג אחוז תפוסת פורטים בפס צבעוני. מסדי EOR מסומנים בכתום.
2. **לחיצה על מסד** פותחת **תצוגת 42U** — כל הרכיבים במיקום ה-U האמיתי
   שלהם, והמקומות הפנויים ביניהם.
3. **לחיצה על רכיב** מציגה את סוגו, הדגם, המיקום, ואת **כל הפורטים**:
   ירוק = פנוי, אדום = תפוס, צהוב = משמש כגישור מעבר. מתחת יש טבלה של
   **לאן כל פורט תפוס מגיע** (הקצה השני + מספר החיבור).
4. **לחיצה על פורט תפוס** ← הממשק מציג מיד את החיבור הקיים ומדגיש על המפה
   את כל המסדים שהוא עובר דרכם.
5. **לחיצה על שני פורטים פנויים** (מקור ואז יעד) ואז **SHOW ROUTE** ←
   המנוע מחשב מסלול חדש, מדגיש אותו על המפה, ומציג Work Order מלא שאפשר
   להוריד כקובץ.

אפשר לכפות רגל רדונדנטיות מסוימת דרך תיבת הבחירה "דומיין" בראש המסך.

## מבנה החווה שמודל

```
POD A                                    POD B
 שדרה S:  [S01=EOR] S02 … S10             שדרה S:  [S01=EOR] S02 … S10
 שדרה N:  N01 … N09 [N10=EOR]             שדרה N:  N01 … N09 [N10=EOR]
```

- שני פודים, בכל פוד שתי שדרות (S ו-N), 10 עמדות בכל שדרה.
- שמות: `<פוד>-<שדרה><מספר>` → `A-S01`, `A-S07`, `B-N04`.
- **EOR אחד לכל שדרה, בקצוות מנוגדים**: בשדרה S ה-EOR יושב בעמדה 01,
  בשדרה N הוא יושב בעמדה 10. כלומר בכל שדרה יש EOR + 9 מסדי מחשוב.
- כל מסד הוא **42U**, ובתוכו רכיבים במיקומי U אמיתיים. **הפורטים שייכים
  לרכיב**, לא למסד — בדיוק בגלל זה ה-Work Order יכול לומר
  "U42, FIB-PP-01, פורט 12".

### רדונדנטיות A/B

- **דומיין A** = כל מה שעובר דרך ה-EOR של שדרה S.
- **דומיין B** = כל מה שעובר דרך ה-EOR של שדרה N.
- כל מסד מחשוב, **בשתי השדרות**, מחובר בגישור לשני ה-EOR. זו הנחה שקבעתי
  כדי שאפשר יהיה לנתב זוג חיבורים מיותר עם **אפס מקטעים פיזיים משותפים**.
  אם בפועל מסד מחובר רק ל-EOR של השדרה שלו — מוחקים את הגישור השני
  ב-`build_edges()` והמנוע ימשיך לעבוד (פשוט בלי A/B ברמת מסד בודד).
- בין הפודים: רק EOR ל-EOR, **סיב בלבד**, ובאותו דומיין:
  `A-S01 ↔ B-S01` (דומיין A), `A-N10 ↔ B-N10` (דומיין B).
  אין נחושת בין פודים — ולכן בקשת חיבור נחושת בין-פודית **נכשלת נכון**
  במקום להמציא מסלול.

### הנחות מספריות (כולן ב-CONFIG בראש `generate_topology.py`)

| פריט | ערך |
|---|---|
| מסד מחשוב | פאנל סיב 24 (U42), פאנל נחושת 24 (U41), ToR 48+4 (U40), 4–10 שרתים 2U |
| מסד EOR | 5 פאנלי סיב HD 48 · 9 פאנלי נחושת HD 48 · 2 מתגי EOR |

## מה נבדק ועובר (`python test_scenarios.py` → 19/19)

**שלמות הנתונים:** תפוסת כל גישור שווה בדיוק למספר החיבורים שעוברים דרכו ·
לכל פורט תפוס יש חיבור משויך · שני קצוות של חיבור מצביעים זה על זה.

**מבנה:** EOR בעמדות S01 ו-N10 בכל פוד · כל מסד 42U · כל רכיב במיקום U חוקי
עם פורטים משויכים.

**ניתוב:** חיבור באותה שדרה · חיבור בין שדרות בתוך פוד · חיבור בין פודים
בדומיין A ובדומיין B · **שתי הרגליים לא חולקות אף מקטע פיזי** · נחושת בין
פודים נדחית · אי-התאמת סוג כבל נדחית · פורט שכבר מגושר נדחה · גישור מלא
חוסם את הדומיין שלו · במצב אוטומטי המנוע נופל לדומיין השני.

## מה זה עדיין לא עושה (בכוונה)

- **לא כותב שום דבר בפועל.** כל חישוב הוא הצעה בלבד, וכל Work Order מסתיים
  ב-`STATUS: PROPOSED — Requires network engineer approval`. זה תואם להחלטה
  שבשלב הראשון כתיבה חוזרת תתבצע רק אחרי אישור מהנדס.
- **אין עדיין חיבור ל-API של ITA.** כשתהיה גישה, שתי הפונקציות שצריך לממש
  מחדש הן `load_topology()` (קריאה) ו-`commit_route()` (כתיבה) בתוך
  `pathengine.py`. כל לוגיקת האילוצים לא צריכה להשתנות.
  `commit_route()` כבר כתובה בדיוק בצורה שתשמש לכתיבה חזרה — היא זו
  שמייצרת את 260 החיבורים הקיימים בדאטה.
- **גישור מעבר ב-EOR מיוצג כפורט אחד** ולא כזוג (כניסה/יציאה). פישוט מודע.
- **Work Order הוא טקסט** לצורך מהירות איטרציה. אחרי שהלוגיקה מאושרת קל
  להפוך אותו למסמך Word מעוצב להדפסה.
